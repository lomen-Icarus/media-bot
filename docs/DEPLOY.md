# Деплой

Бот рассчитан на тот же хостинг, что и vish-bot: Pterodactyl (FrienWorld), egg **Node.js generic**. Нужен **отдельный сервер** в панели: свой процесс, своя база, и деплой не перезапускает vish-bot и записывалку вебинаров. Открытый порт не нужен: оба мессенджера работают через long polling.

## 1. Боты

1. **Telegram:** @BotFather → `/newbot` → токен. Описание и картинку можно поставить там же.
2. **МАКС:** business.max.ru → «Чат-боты» → новый бот (нужен верифицированный профиль ИП или организации, как у бота ВИШ) → после модерации токен: бот → «⋮» → «Настройки».
3. Можно запускать и с одним токеном: второй мессенджер просто не включится.

## 2. Сервер в панели

```
/home/container
├── index.js       # лаунчер: при Node < 22.19 сам скачивает портативный Node 22 (как у vish-bot)
├── dist/          # собранный бот
├── package.json   # зависимости ставит egg (npm install) при старте
├── .env           # секреты — создать вручную: Files → New file
└── data/          # media-bot.sqlite (вотермарки, люди, настройки) + batches/ (временные фото)
```

Стартовая команда egg'а подходит без изменений: `npm install` + `node /home/container/index.js`.

**sharp** — это готовый бинарник `@img/sharp-linux-x64`, обычный npm-пакет без `node-gyp`. Он ставится так же, как `@resvg/resvg-js` в vish-bot, поэтому ограничение FrienWorld на `utime()` его не задевает. Если в логе старта будет `Could not load the "sharp" module`, напишите: тогда понадобится образ на glibc, а не на musl.

## 3. `.env`

| Переменная | Что |
|---|---|
| `BOT_TOKEN` | токен Telegram |
| `MAX_BOT_TOKEN` | токен МАКС |
| `TG_ADMIN_IDS`, `MAX_ADMIN_IDS` | админы через запятую. Свой id бот присылает по `/id`. **Админ должен хоть раз написать боту в этом мессенджере**, иначе бот не сможет прислать ему запрос на доступ |
| `TG_ALLOWED_IDS`, `MAX_ALLOWED_IDS` | необязательно: кого пускать без запроса. Остальных админ пускает кнопкой |
| `DATA_DIR` | `./data` |
| `BATCH_TTL_HOURS` | сколько часов хранить присланные фото для переделки кнопками (по умолчанию 6) |
| `LOG_LEVEL` | `info` |

## 4. Автодеплой из GitHub

`.github/workflows/ci.yml`: на каждый push в `main` — typecheck, тесты, сборка, затем загрузка архива на сервер панели и перезапуск. Нужны секреты репозитория **media-bot** (Settings → Secrets and variables → Actions):

- `PTERO_PANEL_URL` = `https://panel.frienworld.space`
- `PTERO_API_KEY` — тот же Client API key, что и у vish-bot (или новый)
- `PTERO_SERVER_ID` — id **нового** сервера (не `b7f95b74` — это vish-bot)

Без секретов CI просто пропускает деплой и остаётся зелёным.

## 5. Первый запуск — проверка

1. В консоли панели должно быть `media-bot starting`, затем `telegram bot authorised` и `polling telegram`, `MAX bot authorised` и `polling MAX`.
   - `MAX not reachable, retrying` — МАКС не ответил; бот сам повторяет, Telegram работает.
   - `MAX_BOT_TOKEN не подходит (401)` — токен скопирован не целиком.
   - `telegram not reachable yet, retrying` — нет связи с api.telegram.org.
2. Админ пишет боту `/start` → «⚙️ Настройки» → «🗂 Вотермарки в базе» → «➕ Добавить» → присылает PNG с прозрачным фоном **файлом**, в подписи — название.
3. Присылает 2–3 фото файлом → получает файлы с вотермаркой → жмёт «📍 Место» → «↖️» → старые файлы заменяются новыми.
4. То же в МАКС. **Это нужно проверить вживую** (из песочницы МАКС недоступен):
   - уходят ли несколько файлов **одним сообщением**. Если МАКС откажет, бот сам перейдёт на «по одному» — в логе будет `MAX rejected several files in one message`;
   - фото, отправленное в МАКС «как фото», не пересжато ли. Сравните размер в пикселях результата с оригиналом; если пересжато, бот нужно научить подсказывать «отправляй файлом», как в Telegram.
5. Админ: `/stats` — фото, пачки и какие кнопки под результатом жмут (на этом основании решаем, что оставить на виду).

## Бэкап

Всё ценное — в `data/media-bot.sqlite`: вотермарки, люди, доступ, настройки. Бэкап — копия файла (лучше при остановленном боте). `data/batches/` — временные файлы, их бэкапить не нужно.
