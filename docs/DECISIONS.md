# Решения

| № | Что | Почему |
|---|---|---|
| 1 | Отдельный бот, а не функция vish-bot | По выбору владельца. Студентам не нужна лишняя кнопка, а деплой бота вотермарок не перезапускает записывалку вебинаров. |
| 2 | Одно ядро + адаптеры, а не мост «МАКС → Telegram», как в vish-bot | В vish-bot мост выбран, потому что под Telegram уже было ~9 тыс. строк интерфейса. Здесь бот пишется с нуля, поэтому ядро сразу говорит на общем интерфейсе `Messenger` (4 метода) и ничего не переводится. Клиент МАКС (`src/max/api.ts`, сертификат Минцифры) взят из vish-bot. |
| 3 | Доступ — только по списку | По выбору владельца: бот для медиакоманды, а картинки грузят сервер. Админы и доступ из `.env` — отдельно по мессенджерам. Остальные просят доступ сами: админам приходит запрос с «✅ Пустить / 🚫 Нет» (не чаще раза в сутки от человека), а у «🚫» есть «↩️ Всё же пустить». |
| 4 | Вотермарки добавляют только админы | По выбору владельца. Вотермарка хранится в SQLite как PNG (длинная сторона ≤ 4000 px), прозрачные поля по краям обрезаются, чтобы отступ от края был точным. Сжатое мессенджером фото как вотермарка не принимается, потому что прозрачность уже потеряна. |
| 5 | Сразу файлы + кнопки под результатом, без превью | По выбору владельца. Ежедневный путь — 1 действие. Правка — 2 нажатия: бот переделывает ту же пачку (оригиналы лежат на диске `BATCH_TTL_HOURS`), сначала присылает новое, потом удаляет старое (если отправка не удалась — старое остаётся, и есть «◀️ Назад») и запоминает выбор как умолчание. |
| 6 | Размер — от короткой стороны фото | Иначе на горизонтальном фото логотип был бы крупнее, чем на вертикальном из той же съёмки. Процент — это длинная сторона вотермарки, поэтому одинаково ведут себя и широкие, и высокие логотипы. |
| 7 | Качество JPEG — по таблице квантования, не ниже 92 | Числа «качество» в файле нет, а таблица яркости у libjpeg — стандартная, умноженная на коэффициент. Пересжимать исходник 70 с качеством 70 значит добавить второе поколение артефактов, поэтому минимум 92. Пересжимать 97 с качеством 92 значит потерять качество, поэтому берётся качество исходника. Субдискретизация и прогрессивность — как у исходника. |
| 8 | Результат — документом | Иначе Telegram пересжимает картинку. Альбом документов — до 10 файлов и до 50 МБ на запрос (лимит Bot API на файл; про общий лимит запроса документации нет, поэтому берём с запасом). |
| 9 | Long polling в обоих мессенджерах | Порт и HTTPS не нужны. МАКС советует вебхук для продакшена; при нагрузке медиакоманды long polling достаточно, но это стоит пересмотреть. |
| 10 | Картинки обрабатываются по одной на весь бот | Фото 48 Мп — ~0,6 с и ~200 МБ памяти. Параллельная обработка на маленьком сервере закончилась бы нехваткой памяти. Пачки одного человека идут по очереди. |
| 11 | Мессенджеры стартуют независимо | Недоступен один — второй работает. МАКС при старте ждёт сеть с паузой до 5 мин, Telegram повторяет через autoRetry. Неверный токен МАКС (401) останавливает только МАКС. |
| 12 | Логи — только id и цифры | Как в vish-bot: без имён и текстов. Имена людей хранятся только в базе на сервере — для списка «👥 Доступ» у админа. |
